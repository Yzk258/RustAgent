# RustAgent

背景详见：RustAgent\Background.md文件，该项目初衷是设计一款智能化管理MC游戏mod的agent。

项目痛点：

1. 与朋友游玩mc时，常常因现有mod或整合包已玩腻，又不知道有其他哪些好玩的mod，相关信息基本强依赖自己在社区的大海捞针、或是博主的视频解说
2. 自己配置mod整合包时又常常被不同mod相互不兼容所困扰，一次一次人工检查mod信息效率低下

核心功能：

1. 根据玩家提供的需求，agent自动调用modrinth相关api去获取相关mod，最后整理出一份整合包，玩家可自己筛选其中的mod觉得是否喜欢；
2. agent存有用户数据库，随着mod整理与玩家反馈，agent逐渐了解玩家mod胃口并保存相关数据，便于以后的更精准获取mod；
3. 引入“试试这个”窗口，每天或每隔一段时间，agent获取最新mod信息，根据用户数据库推测并向玩家供应对应的mod；
4. 调取mod信息时，agent根据玩家对版本、特色等的描述，自动筛选不符合版本和要求的mod，以及多个mod整合包存在冲突风险时，agent基于mod元数据（版本、加载器、依赖关系等）检测出潜在冲突的mod并汇报。
5. 引入llm接口，支持用户以本地部署大模型或apikey远程调取方式实现交互。

基础功能（作业固定要求 R1–R6）：

1. 核心逻辑以 Rust 实现：agent框架、任务调度、api调用编排、数据处理均在 Rust 中完成；
2. 用户交互界面：先实现 CLI 交互式终端（触发任务、展示结果），视进度扩展 Web 界面；
3. 可自定义模型配置：通过 config.toml / .env 配置 API Endpoint、API Key、上下文长度、思考模式、API 价格等，可在 OpenAI 兼容远程模型与本地部署模型（如 Ollama）之间自由切换，并支持在 CLI 设置页修改；
4. 实时进度渲染与打断：耗时超过 3 秒的任务（批量检索、下载 mod、逐个兼容性检查等）实时渲染进度（如“已检查 45/120 个 mod”），并允许用户随时打断；
5. 上下文历史管理：保存多轮对话与任务状态历史，用户可查看历史任务、保存/加载某次会话的完整上下文（JSON 格式），并展示 agent 背后实际的工作流程轨迹；
6. Token 用量与价格统计：精确统计每次 API 调用的输入/输出 token 数，按配置的模型价格实时换算成本并在界面清晰展示；支持设置 token 预算，用量到达预算时自动中断。

预计实现方式：

1. 核心agent框架以rust形式实现
2. 核心功能以skill形式搭载在不同llm上
